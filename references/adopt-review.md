# Adopt Review on a regular skill

Use when the user wants an existing skill (or a newly authored one) to show up correctly on Feishu Review and to support `/<skill> -review`.

**读法:** § Checklist is the whole retrofit. § Fleet adapt when Preflight found gaps. § Verify after writing. Authoring norms for the companion files live in `skill-authoring.md`.

Work in the **current agent app’s default skills root** (`open-review.md` § Skills root). 

## What “supports Review” means

A skill supports Review when all of the following are true:

1. The overview (`/skills-check`) can scan it and render 简介 / 能做什么 / 使用方法 / 执行步骤.
2. `/<that-skill> -review` opens **that** skill’s single page (not the overview).
3. Its `scripts/open-review.ps1` points at **this** skill’s viewer: `skills-check/scripts/skills-check-viewer.py`.

## Checklist (required files)

Do this in the **target skill directory** under the current skills root.

| File | Audience | What to put |
|------|----------|-------------|
| `SKILL.md` | Agent | Thin hub. Add a Commands row: `-review` → `scripts/open-review.ps1`. Do not add `-reviewall`. |
| `README.md` | Human | **Required.** English. After the `#` title: `[中文](README.zh.md)`. Order: untitled intro → `## Install` (one **English** agent prompt: git URL + Steps; no human `git clone`) → `## Features` → `## How to use` → `## Common changes`. Those three are the whole content block: no `When` / `How to invoke`, no file-roles or layout table. Do not use a specific agent app name. Missing, no Chinese entry, Chinese prompt in this file, or wrong order = 缺件. Templates: `skill-authoring.md` § Install prompt. |
| `README.zh.md` | Human | **Required.** Chinese. After the `#` title: `[English](README.md)`. Same facts and order: 简介 → `## 安装`（**中文** Agent 提示词：仓库地址 + 步骤）→ `## 功能介绍`（能做什么，短列表）→ `## 怎么用`（你说什么 → 会发生什么；何时触发写在引导句里）→ `## 常见改动`（想改什么 → 对 Agent 说的一句话）。不写 `何时` / `怎么调用` / 文件角色 / 目录清单表. Do not use a specific agent app name. Missing, no English entry, or wrong order = 缺件. |
| `review-intro.md` | Human | One short **Chinese** plain-text paragraph for Feishu 简介. No `**bold**`, no `` `code` ``. Do not use a specific agent app name. |
| `review-body.md` | Human | Chinese `## 能做什么` and `## 执行步骤` (last on the page). Split 能做什么 only when jobs are loosely related. Every item has a matching `###` — even one step. Bold **only the lead label** before `：`. Do not use a specific agent app name. |
| `review-usage.md` | Human | Chinese `## 使用方法` as one sentence (常驻 / `@` / 关键词). `## 功能` + `### <能做什么标题>` + `####` 命令/参数/脚本/工具. **Omit** `-review` and `/skills-check` on domain skills. No agent-only script list, no `## description 内容`. Do not use a specific agent app name. |
| `tag.txt` | Human / Review | One UTF-8 line. Multiple tags: comma-separated. Propose, then write what the user confirms. |
| `scripts/open-review.ps1` | Agent | Generated — do not hand-write a different viewer path. See § Generate opener. |
| Three layers | Agent | `SKILL.md` indexes `references/` (or `modules/` / `standards/`) and `examples/` — `skill-authoring.md` § Three layers. Stub-only `examples/` does not count. |

Optional but recommended when the skill already has `references/` or `scripts/`:

- `references/cross-reference.md` — record that `open-review.ps1` is invoked by `SKILL.md` `-review` and generated by this viewer.
- `references/hub-norms.md` File index — one row for `scripts/open-review.ps1`.

## Fleet adapt (Preflight)

When `open-review.md` § Preflight lists unadapted skills, apply § Checklist to **each** of them in this turn before opening Review.

- Extract `review-intro.md` / `review-body.md` / `review-usage.md` / `README.md` / `README.zh.md` from that skill’s existing hub and docs. Write only what those files already say.
- If `tag.txt` is missing, write one short tag from the folder name and tell the user they can rename it.
- Add the `-review` Commands row if missing.
- After the last skill, run `--write-open-scripts` once for the whole root.

## SKILL.md Commands row

Every Review-capable skill uses the same agent flag. Example:

```markdown
| `-review` | Open this skill’s Feishu Review — `scripts/open-review.ps1` |
```

Keep `-review` on the **agent** hub only. The human Review page (`review-usage.md`) of a domain skill does not list it.

## Generate opener

From any machine that has this skill installed:

```powershell
python "<skills-check>/scripts/skills-check-viewer.py" --write-open-scripts --print
```

This writes/overwrites `scripts/open-review.ps1` in **every** skill under the current skills root so they all call `skills-check\scripts\skills-check-viewer.py --skill <that-folder>`.

If you are adopting only one new folder and the template has not changed, you may copy an existing sibling `open-review.ps1` — the generated body is identical across skills (it discovers its own folder).

## review-usage.md shape (domain skill)

Write only sections that have real content:

1. `## 使用方法` — one sentence on how to invoke. No `###`.
2. `## 功能` — under `### <能做什么标题>`, only `####` 命令 / 参数 / 脚本 / 工具. Skip when none. Do not list `-review` or `/skills-check` on domain skills.

## After authoring the companions

Follow `skill-authoring.md` § Synchronize companion files and § Positive / negative norms. The viewer’s `pos_neg_pair` check flags unpaired Must-not and redundant paren negatives as 需关注.

## Verify

1. `/<skill> -review` → single page `#/skill/<folder>`; 简介 / 能做什么 / 怎么用 match the three `review-*.md` files.
2. `/skills-check` → overview card for that folder (tag + intro + health checks).
3. `scripts/open-review.ps1` contains `skills-check\scripts\skills-check-viewer.py`.

## Must

- Add the companion files in the table above (README pair + Review three pages), then generate `open-review.ps1` from this skill’s viewer.
- Keep `/<skill> -review` as the single-page entry; keep `/skills-check` as the overview entry.
- Write 当前 Agent / Agent; do not use a specific agent app name.

## Must not

- Point `open-review.ps1` at `jeffrey-workflow-skill/scripts/skills-check-viewer.py`. *(← Must: viewer lives in this skill)*
- Add `-reviewall` to the target skill. *(← Must: overview is `/skills-check`)*
- List `-review` / overview on the target skill’s `review-usage.md`. *(← Must: those flags stay on the agent hub / this skill’s Review page)*
